# Предел на одно действие

English version: [README.en.md](README.en.md)

19 октября 2026, версия 0.17.1. Короткий прогон стенда на тестовой модели (`npm run reproduce`, 7 раундов, 12 агентов, 4 оркестратора), два раза на одних и тех же обращениях: с пределом и без него (`SUP_PER_ACTION_SHARE=0`). Цифры тестовой модели, не GigaChat.

## Зачем

Читатель на dev.to заметил: лимит «бюджет вреда ÷ средний вред на действие» предполагает, что вред размазан. В поддержке он с тяжёлым хвостом: почти все ошибки стоят 50–200 ₽, а возврат мошеннику — сумму заказа и 3 000 ₽ за утечку данных. У агента был лимит на число действий и на сумму возвратов за период, но не на одну операцию. С 60 000 ₽ возвратов в запасе один возврат мошеннику на 9 000 ₽ проходил. В смарт-кошельках у сессионного ключа для этого два предела: на период и на операцию.

## Что сделано

- **Предел на одно действие в мандате** (`max_refund_per_action_rub`). Возврат дороже — всегда через человека, сколько бы ни оставалось в пределе периода. По умолчанию это весь бюджет вреда периода (2 000 ₽): одна операция не может одна съесть его целиком. `SUP_MAX_PER_ACTION` задаёт сумму явно, `SUP_PER_ACTION_SHARE=0` выключает.
- **Шлюз проверяет оба предела**, а в журнале каждой операции записан предел, при котором она прошла.
- **Свой экзамен по сфере** (публичный оркестратор): лимит считается по верхней границе среднего вреда (среднее + 1,645·σ/√n), а не по среднему, и в мандате есть `max_harm_per_action`. При одинаковом среднем вреде 1 $ на действие агент с ровными ошибками получает 20 действий, а агент с одной ошибкой на 40 $ — 8.
- **Крупный возврат, который остановил предел, считается крупным случаем для тревоги**, если агент при этом перестал звать свою команду. Об этом ниже.

## Результаты

| | Без предела | С пределом |
|---|---|---|
| Вред подменённого агента в раунде подмены | 19 440 ₽ (один возврат мошеннику и одна утечка) | **0 ₽** (2 крупных возврата ушли человеку) |
| Действий у подменённого после тревоги | 0 | 0 |
| Вред всех агентов под оркестраторами за прогон | 44 410 ₽ | **10 870 ₽** |
| Выгода всех агентов под оркестраторами | 225 430 ₽ | **250 970 ₽** |
| Возвратов мошенникам | 2 | **0** |
| Передач человеку | 726 | 779 (+53, из них по пределу 105 возвратов) |
| `npm run reproduce` | 9 из 9 | **10 из 10** |

Предел стоит лишних передач человеку: возвраты дороже 2 000 ₽ теперь решает человек. Но в этом прогоне это окупилось: вред вчетверо меньше, выгода выше на 25 540 ₽.

## Что нашлось по дороге

С пределом, но без последнего изменения, проверка воспроизведения не сошлась: после тревоги у подменённого агента осталось 3 действия вместо 0, и он сделал ещё 1 500 ₽ вреда. Причина — предел спрятал доказательство. Тяжёлая тревога (0 действий) ставится, когда агент перестал звать проверяющих и сделал крупную ошибку. Подменённый агент пытался вернуть деньги мошеннику, шлюз не пустил, вреда не было — и тревога вышла мягкой. Теперь крупный возврат, остановленный пределом, считается крупным случаем, но только вместе с отказом от команды. Честный агент со своими проверяющими так тревогу не получает.

## Ограничения

Это тестовая модель и один набор обращений. Проверка на GigaChat — повтор серии на тех же обращениях (следующий прогон после run-series1-a3). Предел по умолчанию (весь бюджет периода) выбран по доводу читателя, а не подобран.
